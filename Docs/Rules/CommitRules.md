# 커밋 메시지 규칙

커밋과 PR을 만들 때 따르는 규칙입니다. 규칙은 이 문서에만 적습니다.

## 형식

```
[Type] 요약
```

- 요약은 50자 이내로 쓰고 명사형으로 끝냅니다. 마침표를 찍지 않습니다.
- 커밋 하나에는 변경 하나만 담습니다. 기능 추가와 버그 수정을 한 커밋에 섞지 않습니다.

## Type

| Type | 쓰는 경우 | 예시 |
|---|---|---|
| `[Feat]` | 기능 추가 | `[Feat] 코인 획득 시 점수 증가 추가` |
| `[Fix]` | 버그 수정 | `[Fix] 점수가 두 번 오르는 문제 수정` |
| `[Refactor]` | 동작은 그대로 두고 코드 정리 | `[Refactor] 플레이어 이동 로직 분리` |
| `[Asset]` | 에셋 추가·교체 | `[Asset] 코인 스프라이트 교체` |
| `[Docs]` | 문서 수정 | `[Docs] 폴더 구조 규칙 갱신` |
| `[Chore]` | 설정·패키지 변경 | `[Chore] Input System 패키지 추가` |

## 브랜치

- `main` 브랜치에 직접 커밋하지 않습니다.
- 작업마다 브랜치를 만들고, 끝나면 `main`으로 PR을 올립니다.

| 작업 | 브랜치 이름 | 예시 |
|---|---|---|
| 기능 | `feature/<짧은-설명>` | `feature/coin-pickup` |
| 버그 수정 | `fix/<짧은-설명>` | `fix/double-score` |

- PR 제목도 커밋 메시지와 같은 `[Type] 요약` 형식으로 씁니다.
